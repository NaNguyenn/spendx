# Stateless JWTs with timestamp-based revocation, not a session table

Password Reset must end all of a User's existing sessions, but sessions are stateless JWTs with no server-side record. Rather than introduce a session/refresh-token table, we revoke by comparison: `User.credentialsChangedAt` is stamped on any credential change, and the auth guard — which already loads the User row on every request — rejects any token whose `iat` predates it. This keeps tokens stateless and payloads unchanged (no mass sign-out on deploy, unlike a `tokenVersion` claim added to new payloads), and generalizes to future credential changes and "sign out everywhere". The trade-off accepted: revocation granularity is all-sessions-at-once — individual sessions cannot be listed or revoked selectively without moving to server-side session state.
